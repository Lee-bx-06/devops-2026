## 3. 结果解释

### 实际图

| target | dependency | 证据 |
| --- | --- | --- |
| `app` | `main.o` | `t.18:82`，pid 18，`ld` 以 `O_RDONLY` 打开 `main.o` |
| `main.o` | `config.h` | `t.14:579`，pid 14，`cc1` 以 `O_RDONLY\|O_NOCTTY` 打开 `config.h`，返回 fd 4 |
| `main.o` | `main.c` | `t.14:67`，pid 14，`cc1` 以 `O_RDONLY\|O_NOCTTY` 打开 `main.c`，返回 fd 3 |

`/usr/include` 等根外路径被 `project_path` 过滤掉；`unused.h` 只有 `t.12:46` 的 `newfstatat`（make 检查先决条件），没有成功 `openat(... O_RDONLY)`，所以不计入实际图。

### 声明图

| target | dependency | `make-db.txt` 行号 |
| --- | --- | --- |
| `app` | `main.o` | 601（`app: main.o`） |
| `main.o` | `main.c` | 1053（`main.o: main.c unused.h`） |
| `main.o` | `unused.h` | 1053（同上） |

### 检出结果

- `MISSING(main.o, config.h)`：实际读取了 `config.h`，声明里只有 `main.c, unused.h`；证据为读 `t.14:579` 与目标写入 `t.15:23`。
- `REDUNDANT(main.o, unused.h)`：声明了 `unused.h`，但本次 recipe job 没有成功读打开；证据为 `make-db.txt:1053`，`scope` 说明“Not observed in this recipe job under this build configuration”。
- 原始检测入口退出 1 是 `--fail-on-findings` 的预期行为；`findings.json` 的 `status=SUCCEEDED`、`clean_exit_code=0`、`build_exit_code=0`，说明**检出依赖问题 ≠ 工具执行失败**。

### 修复复检

`--fixed` 在独立副本里把 `main.o: main.c unused.h` 改为 `main.o: main.c config.h`。复检结果：

- `findings=[]`，入口退出 0；
- `verify_e6_evidence.py` 输出 `passed=true`；
- 输入哈希只有 `Makefile` 变化（`fd1dcd76… → 128069c9…`），`config.h/main.c/unused.h` 三个哈希不变。

### 进程归属

`make` (pid 12) 下有两个 recipe job：

- `main.o`：`cc` 13 → `cc1` 14（读 `main.c`/`config.h`）、`as` 15（写 `main.o`），`job_pid=13`；
- `app`：`cc` 16 → `collect2` 17 → `ld` 18（读 `main.o`、写 `app`），`job_pid=16`。

`job_for` 沿 parent 向上找到“父进程是 make”的那层，因此 `cc1/as` 归到 13、`collect2/ld` 归到 16；`processes.json` 可逐项回查。
