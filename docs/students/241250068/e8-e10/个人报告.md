## E8：固定 MD 报告与候选补丁

- **输入**：`fixture()` 生成的受限 C/Make 项目。`main.o` 声明 `main.c unused.h`，但 `main.c` 实际 `#include "config.h"`；构建仍能成功，因为头文件存在、编译器能读，只是 Make 缺少触发关系。
- **scan 结果**（`fixed-md-report.json`）：恰好两条
  - `MISSING main.o ← config.h`
  - `REDUNDANT main.o ← unused.h`
- **报告身份**：报告 `commit = 7655d9a6222bfc9e27f38e8ddb87110a2be3241f` 与样例内层 HEAD 一致（`COMMIT_MATCH`）。
- **候选 Patch**（`candidate.patch`，`patch-plan.json` 中 `style=direct`）：
  ```diff
  -main.o: main.c unused.h
  +main.o: main.c unused.h config.h
  ```
  只处理 MISSING；不删 `unused.h`（RD 保留）、不改 TAB 配方与 `CFLAGS`。生成后源 Makefile 仍无 `config.h`（`PATCH_GENERATED_SOURCE_UNCHANGED`）。
- **只检查不写回**：`git apply --check` 通过，内层 `git status --porcelain` 为空（`APPLY_CHECK_PASS_SOURCE_CLEAN`）。此步不证明构建/测试正确，留给 E10 的质量判定。
- **主动拒绝旧报告**：把报告 `commit` 改为 40 个 0 后 `patch()` 抛 `STALE_REPORT`，原 Makefile 逐字节未变（`SOURCE_BYTES_UNCHANGED`），证据在 `expected-failure.json`。
- **结论**（`结论.txt`）：候选仅增加 config.h；保留 RD 和配方；旧报告拒绝；尚待 E10 质量验证。

## E9：三种声明风格的补丁

内层项目 C0 提交：direct = `072f2e1bc4f6db9478877155bf2f206db65b3cd1`；macro = `6a83fc1ec592bda6974d00f5e7e49c6e78e653b0`；mixed = `e7d3941f8db8642e9635510b15dc3d4ba435cbcc`。三个项目各自独立。同一个 MD，落点不同：

| 风格 | 原声明 | 补丁改在哪里 | 结果 |
|---|---|---|---|
| direct | `main.o: main.c unused.h` | 目标依赖行行尾追加 `config.h` | `STYLE_PASS direct` |
| macro | `DEPS = main.c unused.h`；`main.o: $(DEPS)` | 改变量定义 `DEPS = main.c unused.h config.h`，目标行仍引用 `$(DEPS)` | `STYLE_PASS macro` |
| mixed | `HEADERS = unused.h`；`main.o: main.c $(HEADERS)` | 目标依赖行行尾追加 `config.h`，保留 `$(HEADERS)` 宏引用 | `STYLE_PASS mixed` |

- 三次生成都断言原 Makefile 字节不变；`git apply --check` 均通过 → 补丁只是候选，落地与否由 E10 判定。
- 额外副本 `apply-demo/` 由 macro 项目复制而来，应用 `macro.patch` 后 `DEPS = main.c unused.h config.h`，原 `macro/` 项目仍无 `config.h`（`APPLY_TO_COPY_PASS`）。
- 代码位置：`labs/e8e10/lab.py:76 def patch()`；`STALE_REPORT` 在 77 行；`UNSAFE_PATH` 在 82 行；`UNSUPPORTED_RULE/DECLARATION/FLAGS/TARGET/MACRO` 在 40/44/50/85/89 行。
- **结论**：direct 修改目标行；macro 修改 DEPS 定义；mixed 保留宏引用并修改目标行。共享变量被其他目标引用时，直接改变量会扩大作用范围，需要声明图级别的扩展分析。
